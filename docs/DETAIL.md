# 追问线（Follow-up thread）

在任意一条已经完成的回答下方就地追问：问题与回答一起显示在那条回答之后，上下文接着那条回答走，而不是把问题丢到对话最底部、让上面的回答被顶走。

## 用起来是什么样

- 每条回答结束后的操作行上方（`conversation.chat.turnTail`），默认只有一行很轻的入口：`＋ 追问`。
- 点开出现输入框，写下问题，**Enter 发送**；`Shift + Enter` 换行。
- 有了一条追问后，这一行变成 `▾ 追问 N`：点开是**按问题命名的清单**，选中哪条才展开哪条的回答（同一时刻只显示一条，避免一屏全是展开的卡片）。
- 折叠/展开状态与当前选中的条目按会话记在浏览器 `localStorage`（`dsh.followup-thread.v1:view:<会话 id>`），刷新或切走再回来都保持。
- 出错时问题不丢：卡片上保留 `重试` 并附一行诊断；也可以用 `删除` 移除这条追问。

## 它是怎么工作的

追问不新建会话，回答由宿主直接算出来：

1. 客户端 `POST ./api/followup-thread/ask`，请求体 `{ sessionId, atSeq, question }`。
2. 宿主侧路由读取该会话的事件（`session.snapshotEvents()` 等回退读者），把 `atSeq` 之前的对话**回放**成模型消息：用户文本、助手文本、`[调用 <工具>] <参数>`、`[工具结果 <工具>] <输出>`；工具参数截到 400 字、结果截到 1500 字，总预算 8 万字符，**从靠近那条回答的一端往前取**，保证长会话也不会丢掉上下文。
3. 用这个会话自己最近一次的模型路由（`agent.model.current()`，回退到 `model/selection`、`request/header` 事件）调用 `ctx.llm.stream({ provider, model, messages })`，把 `text-delta` 拼成回答返回。
4. 回答写在浏览器本地，跟着那条回答显示。

因为整条链路里没有 Session、没有 fork，**左侧工作区不会多出任何会话**；也因为没有写入会话事件，回放、分支、导出都不受影响。

## 与其它做法的区别

- 不用「在新对话中分支」：那会在左侧真的多出一个会话，还要手动归档。
- 不用子会话（subagent）：`origin: 'subagent'` 的会话同样会以缩进行形式出现在会话列表里。
- 不改写会话日志：不新增事件类型，不塞插件私有记录。

## 限制

- 追问看到的是**截止那条回答**的上下文，之后的对话它看不到（会说明「之后的对话我看不到」而不是编造）。
- 追问是一次性的只读回答：不调用工具、不写文件、不改代码。
- 回答以纯文本显示（保留换行），不在卡片里还原 Markdown 排版。
- 每条追问都存在本机浏览器里，不随会话同步到其它设备。
- 宿主侧代码（`index.js`）更新后需要重启应用才生效；客户端（`client.js`）刷新窗口即生效。

## 卸载

在插件管理里停用或移除 `dsh-followup-thread`；浏览器里残留的 `dsh.followup-thread.v1:*` 键可以手动清掉。
